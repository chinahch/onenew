# Private source and public distribution

Public node binaries, corresponding native source and standalone shell scripts are published to `chinahch/onenew-releases`. The Worker at `get.timi.baby` reads those public scripts dynamically; normal script/version updates do not require another Worker deployment. No panel source, APP_KEY, database or machine credentials are published there.

## Publication credential (GitHub Actions only)

Create a fine-grained token whose selected repository is only `onenew-releases`, with Contents read/write. Save it as the `ONENEW_RELEASE_TOKEN` Actions repository secret in **chinahch/onenew**, where the workflow runs. Do not use it on panel or node machines. Replace the secret before its chosen expiration.

The native workflow never overwrites published binaries. It publishes the corresponding prepared native source and atomically refreshes only three public shell entrypoints after successful native verification. Panel source remains in the source repository.

## Read-only source credential (panel host only)

Create a different fine-grained token: selected repository **onenew**, Contents **read-only** (Metadata read-only is automatic). On the panel host, in a root Bash terminal, save it without putting the value in shell history:

```bash
install -d -m 700 /root/.config/onenew
umask 077
read -rsp 'GitHub source read-only Token: ' ONENEW_SOURCE_TOKEN; echo
printf '%s\n' "$ONENEW_SOURCE_TOKEN" > /root/.config/onenew/github.token
unset ONENEW_SOURCE_TOKEN
chmod 600 /root/.config/onenew/github.token
```

This is a GitHub token, not a node machine token. A fresh destination panel host also needs the read-only credential before restoring from a private source repository. It is deliberately not placed in the application container, migration package, download URL or process arguments. Node machines do not need it. If no file exists, downloads remain anonymous for the staged public-to-private transition; a private-source download failure stops before deployment data is changed.

## Commands

Node install/upgrade commands generated by the administrator UI use `/install` and `/upgrade` and carry machine credentials on stdin automatically. The short entry downloads and hashes the complete installer before running it, and handles sudo via the terminal.

For panel upgrades, use the full 40-character desired revision:

```bash
bash <(curl -fsSL https://get.timi.baby/panel/upgrade) --revision REVISION --target /opt/onenew-xb-restored
```

The migration page generates `/panel/restore` commands with the package revision. Both panel scripts use the protected source credential automatically. They retain their existing backup, version pinning, validation and refusal-to-overwrite behavior.

## Final visibility gate

Before changing source visibility, verify public downloads, a full native publication, panel deployment with the read-only credential, and migration restoration. Public forks cannot directly become private. GitHub's Leave fork network operation is permanent and can discard issues, PRs, releases and other metadata while retaining Git commits. Back up metadata and obtain the owner's explicit choice for that consequence, or use GitHub Support to retain metadata. Do not delete the repository to detach it automatically.
