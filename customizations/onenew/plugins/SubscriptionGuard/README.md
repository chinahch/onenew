# 订阅防护（SubscriptionGuard）

原作者：**XBoard Plugin**。本适配基于用户提供的 SubscriptionGuard 1.0.0，版本 1.0.1；来源校验见 NOTICE.md。

在 Onenew 原生“插件管理”中配置、启用和禁用。安装后默认禁用；启用后的默认处理模式为 `alert_only`，只保存本地告警，不封禁、不重置订阅、不发送 Telegram。需要自动处罚时，由管理员明确选择 `auto_ban` 或 `reset_only`。管理员和员工账号始终受保护。

启用后，原生插件菜单提供只读“订阅拉取日志”和“防护事件”，所有数据接口均要求 Sanctum 管理员身份。也可在当前后台安全路径后追加 `/subscription-guard` 打开独立日志页；页面本身只含静态外壳，数据和人工操作仍要求已登录管理员。配置与启停继续使用原生插件管理。

检测窗口为 1–168 小时，最大独立 IP 数为 1–1000。**严格超过**配置的最大值才触发，达到最大值仍允许。IPv6 先规范化，IPv4 映射地址合并为 IPv4；白名单支持 IPv4/IPv6 的单地址和合法 CIDR。启用子网合并时仅合并 IPv4 /24，先排除白名单再分组。重复拉取限频按用户和 IP 计算。防护事件每用户一小时最多触发一次。

多 IP 拉取可能来自移动网络、双栈、客户端更新器或反向代理，并不足以单独证明共享。启用自动处罚前应核对 `TrustProxies` 配置以及 `request()->ip()` 实际取值，配置适当白名单，并先观察告警模式。代理转发头的信任边界由宿主应用决定，本插件不会自行信任任意客户端头。

日志不保存订阅令牌，客户端信息中的当前订阅令牌会被替换。旧版升级迁移会删除原始 `token` 列。该删除不可恢复；升级前按面板正常流程备份。Laravel 告警中仅包含用户 ID、IP 数和处理模式，不包含邮箱、IP 列表、令牌、SQL 或请求头。

日志保留 1–365 天，建议至少覆盖检测窗口。每日 03:00 的清理依赖宿主计划任务；启用状态下也可运行 `php artisan subscription-guard:cleanup --days=30`。解封操作保留历史审计记录，并设置管理员复核时间；已复核历史不会再次触发处罚。人工封禁、解封和清理要求二次确认请求字段。

通知选项默认关闭。显式打开时只通过宿主 Telegram 队列发送用户 ID、IP 数和处理结果，不发送凭据或完整 IP 列表。测试不会发送外部消息。限频和惩罚使用原子缓存操作及每用户锁；缓存/数据库不可用时本次防护跳过，订阅不因防护故障被封禁。
