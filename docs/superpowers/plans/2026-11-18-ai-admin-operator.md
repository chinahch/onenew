# AI administrator operations and source tools plan

> Execute with subagent-driven-development. User explicitly rejected read-only-only assistant and further energy-policy questions. Implement administrator data operations and actual source access.

## Goal
Natural-language administrator can create users, add arbitrary duration to a specific user's expiry without energy checks, add/update/delete nodes, inspect actual code and propose repository code changes. Existing read-only answers remain. Destructive/financial/business writes require an immutable clear action card and explicit confirmation; no model text directly mutates state. Code changes persist in repository branches/PRs, use CI and review; never edit live container files or run arbitrary shell/SQL. User no longer wants policy questions; use fixed least-surprise operation contracts below.

## Architecture
Existing preview/chat remains outer API consent. Operator chat runs bounded model→tool loops using JSON envelope (no mandatory provider tool-calling capability): {answer:string,reads:[{tool,args}],operations:[{kind,args}],patches:[{path,old_text,new_text}]}. If ordinary text, display as answer with no mutation. Strictly whitelist tools and args server-side; ignore model-generated URLs, SQL, shell, credentials/permissions. Up to 3 read rounds, 5 calls/round, bounded 8 files total and 100KB tool data. Every model read call recorded as sanitized trace, never interpreted as authority.

Automatic read tools: lookup users by explicit ID/email alias, nodes/machines/plans/groups (bounded safe fields); list/read/search maintained project source and runtime app source with path+line+SHA. No .env/database/storage/cert/token or arbitrary filesystem/network access.

## Data operation contract (agent Data)
Namespace App\\Onenew\\AiOperations\\OperatorActions.
- public catalog(): array descriptions for model (JSON-safe kind+args).
- public read(string $tool,array $args):array supports users.lookup, nodes.lookup, inventory (plans/machines/groups). Replies identifiers, safe labels/statuses only; no passwords/UUID/tokens/subscribe URLs. Email input from question can be kept local via alias mapping in root coordinator; explicit numeric ID works.
- public prepare(int $admin,string $kind,array $args):array returns {id,kind,title,summary,before,after,expires_at}, stores encrypted validated args with identity/version fingerprint under admin-owned cache key 10m. No business writes here. Fingerprint prevents stale/reused-ID execution.
- public execute(int $admin,string $id,string $requestId,array $inputs=[]):array under lock/idempotency returns prior result on repeat, transactionally rereads fingerprints then invokes native service/model observers. Execution cannot accept changed prepared args; only separately defined local secret input fields allowed. Record admin audit {admin_id,kind,target ids,requestid,result code,timestamp}, no raw params/secrets.
Kinds:
1 user.create: email (admin supplied), optional plan_id, optional days, optional expiry timestamp. Native UserService::createUser; secure generated initial password (never model-supplied/default-email). Result can reveal generated password to initiating admin only, encrypted cache short-lived; no password in model results/audit. No admin/staff role grants. Duplicate email rejects. Plan membership/quota native logic.
2 user.extend: user_id, amount integer1..3650, unit hours|days|months. Base=max(now,current finite expiry), add duration (months calendar no overflow). Unlimited expiry requires clarification, cannot silently replace. No balance/plan/traffic/UUID/token modifications. Preserve native observer synchronization. Preview before/after timestamps explicit timezone.
3 node.create: template_node_id required for first version (existing validated protocol template), name, host, port, server_port, optional machine_id/group_ids. Clone native protocol configuration locally, clear IDs/metrics/state/landing bindings/custom routes/outbounds like normal copy, validate through existing ServerSave rules, create with normal observers. Missing template/required values produce clear follow-up instead of guessing credential/protocol values.
4 node.update: node_id and allowlisted name/host/port/server_port/show/enabled/machine_id/group_ids/node_speed_limit_mbps; same native validation/observer sync. No arbitrary protocol keys or hidden credentials.
5 node.delete: node_id; card includes exact current ID/name/machine and subscription removal effect. Delete via model/native semantics, fingerprint identity protected. No machine deletion.

## Source and repository tools contract (agent Source)
Namespace App\\Onenew\\AiOperations\\SourceTools: catalog():array; read(string $tool,array $args):array; propose(int $admin,array $patches):array; publish(int $admin,string $id,string $requestId):array.
Read tools source.list/search/read: fixed project paths under /opt/onenew for customizations, /www/app for runtime/app source; no path traversal/symlinks/secret dirs; UTF-8 text .php/.mjs/.json/.css/.vue/.ts/.md only with exclusions (.env, locks, tests fixtures with credentials if not necessary). Returns actual path,line numbers,base SHA and current revision, strict caps. Search bounded. Runtime source is read-only; edits target maintained repository overlay paths, not /www live files; explain source mapping.
Code patches only customizations/onenew/ maintained app/admin/user source + tests. Deny .github/, .env, install/update shell, source private state, binary, vendor, composer scripts. Base is immutable running /opt/onenew/REVISION, base content fetched from fixed https://api.github.com/repos/chinahch/onenew API, no arbitrary URL or shell.
Propose validates exact unique old_text match in base text, file counts <=5, size <=100KB, no new secret strings, immutable diff summary stored encrypted per-admin10m; preview includes path/before/after/diff SHA/base revision.
Publish explicit admin confirmation creates deterministic branch+commit+PR against master using separately configured repo GitHub credential, only that fixed repo; user enters once in backend settings (never chat). Use Contents RW+Pull requests RW, no Workflow permission. No automatic merge or production deployment: result PR/checks links for review; do not pretend generated patch was tested until actual CI status retrieved. Repeat requests idempotent, do not store secret in result/logs.
Source agent owns optional migration encrypted repo_key in singleton and RepoSettings class GET view/save (key_configured only), methods to source/token; root registers routes if needed. It may implement read without repo key via public API/local source; publishing requires key.

## Root coordinator
Own Client/Service/Controller/routes updates + OperatorEngine. Source/Data agents do not edit these shared files. Root handles local alias mapping for explicit email addresses in instructions; outbound question replaces email with stable user_ref aliases, no loss of target for creation/lookup. Model cannot introduce new email targets absent original admin question; aliases resolve only at prepare/read time. Do not send live passwords/API keys to model. UI optional local password entry not required; generated password returned locally only.
Outer chat result includes {answer,actions:[],code_changes:[],trace:[],sources,model,usage}; proposal cards are never accepted from browser except owned IDs. Chat/system now capable of proposing/actions and reading code, must not claim executions until execute response success. Read operations after initial outer confirmation documented; no per-file approval. Retry any external provider call not automatic. Config fingerprint binding retained.
Routes under /api/onenew/admin/ai: existing preview/chat; POST actions/{id}/execute {request_id UUID,confirmed:true}; POST code/{id}/publish same. GET/POST repository settings separate explicit encrypted credentials. Admin-only rate limits; CSRF/auth model same bearer as existing admin. No generic shell/SQL/file-write endpoints.
