# OpenCode Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add and publish a real OpenCode execution backend in the existing assistant.
**Architecture:** Owner-scoped async tasks branch to an authenticated OpenCode session adapter; existing coordinator stays unchanged. Separate encrypted config and explicit runtime permissions.
**Tech Stack:** PHP Laravel, React createElement, Node test runner, OpenCode 1.x HTTP API.
**Spec:** docs/superpowers/specs/2026-11-19-opencode-design.md

## Global Constraints
No exposing secrets, no automatic mutation retries, no fake completion, TLS verification and endpoint pinning, preserve current model backend. Do not claim production deployment.

## Review Focus
- Lost POST acknowledgement must never duplicate code or data changes.
- Permission prompts and remote tools failing cannot be shown as successful execution.
- Switching backends/credentials during a task cannot target a different server.
- Blank passwords retain; clear is explicit; no secrets in UI/progress/errors.
- Browser and PHP config contracts must match and existing deployments migrate cleanly.

### Task 1: Backend and task adapter
- [ ] Add failing tests for config isolation, basic auth, real session flow, dedup, uncertain POST and remote error/permission outcomes.
- [ ] Add migration, config validation, backend-specific readiness/fingerprint, OpenCode session transport and task integration.
- [ ] Run PHP tests in isolated Laravel CI and lint locally. Document real supported API version.

### Task 2: Settings/chat and real-server verification
- [ ] Add failing frontend tests for backend fields, payload preservation and secret clearing.
- [ ] Implement backend selector, OpenCode configuration and chat execution semantics.
- [ ] Verify published OpenCode server health/session/protocol against actual CLI, including tool round trip with deterministic local fake model where feasible.
- [ ] Run admin tests/build and full CI. Write deployment instructions.

### Task 3: Review and publication
- [ ] Independent spec/quality review, fix findings, rerun affected tests.
- [ ] Push PR, attach, verify CI, merge authorized changes, verify master artifact/revision and give owner upgrade command and configuration steps.
